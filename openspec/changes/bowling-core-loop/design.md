# Design

## Context

동기와 범위는 proposal.md를 따른다. 현재 상태에서 설계에 영향을 주는 사실만 적는다.

- Unity 6000.3.24f1, URP 17.3, Input System만 활성화(`activeInputHandler: 1`), XR Interaction Toolkit 3.5.1, OpenXR 1.17.1, Meta OpenXR 2.5.1. Android 최소 SDK 34, ARM64.
- `Assets/Scenes/VRB.unity`는 사실상 비어 있다(Directional Light, Main Camera). 게임 스크립트는 아직 없다.
- `Assets/VRB/bowling-club`은 볼링장 전체를 담은 FBX다(CC BY 4.0, 출처 표기 필요). 레인 4개, 핀 10개(`Bowling_pin001`~`012` 중 10개), 공 30개(거치대 위), 장식물 수십 개가 들어 있다. `Cylinder003` 하나가 정점 약 228,000개, 찻주전자류 장식이 약 70개로, Quest 3S에 그대로 쓰기에는 무겁다. 핀·공 메시는 크기 단위가 레인과 달라(바운딩 40~130, 72) 임포트 스케일 확인이 필요하다.
- 효과음 3개가 이미 있다: `Bowling ball roll.wav`, `Bowling pin hit.wav`, `bowlingstrike.wav`.
- 물리 설정은 기본값이다: Fixed Timestep 0.02, 솔버 반복 6, 속도 반복 1, 슬립 임계 0.005.
- `VRTemplateAssets`와 XRI 샘플(Hands Interaction Demo)이 들어 있으나 볼링과 직접 관련은 없다.

## Goals / Non-Goals

**Goals:**
- Quest 3S에서 안정적인 프레임(72Hz 이상)으로 던지기부터 결과 표시까지 한 바퀴가 돈다.
- 던지기 보정 수치, 핀 판정 기준 같은 튜닝 대상을 코드 밖 설정 값 한곳에 모은다.
- 점수·기록 로직이 Unity와 XR에 의존하지 않아 단위 테스트가 된다.

**Non-Goals:**
- 정통 점수 규칙, 2투구 프레임, 스핀·커브, 기록 저장(B/C 단계).
- 멀티플레이 네트워킹. 다만 로직 분리로 확장 여지를 남긴다.
- 볼링장 모델 전체를 그대로 보여 주는 것. 최적화된 한 레인 환경이 목표다.

## Decisions

### 1. 환경: FBX 전체 대신 한 레인을 직접 구성하고 필요한 메시만 재사용

레인 바닥, 거터, 피트, 뒷벽은 단순 형태의 오브젝트와 박스 콜라이더로 직접 구성한다. FBX에서는 핀·공 메시와 가벼운 장식만 골라 쓴다. 레인과 핀 영역의 시각 품질이 곧 게임 품질이므로 그쪽에 정점 예산을 쓴다.

- 대안: FBX를 통째로 씬에 배치. 정점 수와 드로우콜이 커서 Quest 3S 예산을 넘길 가능성이 높다. 임포트 후 프로파일러로 실제 수치를 먼저 확인하고, 문제가 없는 부분만 남긴다.
- 대안: 외부 툴에서 FBX를 직접 다듬기. 작업 흐름이 늘어서 A 단계에는 과하다.
- 시작 예산은 보이는 삼각형 수십만 이하, 드로우콜 수백 이하로 잡고 실기기 프로파일링으로 조정한다.
- 라이트: 실시간 그림자를 최소화하고 라이트맵을 굽는다. 모바일 URP 기본 에셋을 쓴다.

### 2. 물리 구성

- 핀: 리지드바디, 실제 질량비(핀 약 1.5kg), 캡슐과 구를 조합한 단순 콜라이더, 무게중심을 아래로 낮춘다. 시작 시 정확한 위치에서 슬립 상태로 둔다.
- 공: 구 콜라이더, 질량은 핀의 4~5배, 충돌 감지는 Continuous Dynamic으로 통과를 막는다.
- 프로젝트 물리 설정: 솔버 반복 12, 속도 반복 2, Fixed Timestep 1/90. 리지드바디가 11개뿐이라 비용은 작다.
- 물리 머티리얼: 레인은 마찰을 낮게, 핀은 반발을 낮게 둔다. 수치는 실기기에서 던져 보며 조정한다.
- 대안: 핀을 메시 콜라이더(convex)로 구성. 정확하지만 비용이 크고 접촉이 불안정해지기 쉽다.

### 3. 던지기: XRI 그랩을 쓰되 릴리스 속도를 직접 계산

공은 `XRGrabInteractable`로 잡는다. 잡고 있는 동안 컨트롤러 속도를 매 프레임 링 버퍼에 기록하고, 놓는 순간 XRI가 주는 속도 대신 우리가 계산한 값으로 리지드바디 속도를 설정한다.

```
 컨트롤러 속도 샘플 (최근 ~0.1초)
          |
          v
 [순수 물리]  : 놓는 순간 속도 그대로
 [약함 이상]  : 0.1초 평균 속도
 [중간/강함] : 평균 속도의 방향을 레인 정방향으로 k만큼 보정 (속력 유지)
          |
          v
 리지드바디.velocity  (+ 수직 성분 상한으로 공이 뜨지 않게 제한)
```

- 보정 단계는 `ThrowAssistSettings` 같은 ScriptableObject에 단계별 평균화 여부와 보정 비율을 담는다. 초기값은 약함 0, 중간 약 0.3, 강함 약 0.6으로 두고 실기기에서 조정한다.
- 보정은 방향만 바꾸고 속력은 늘리지 않는다(spec의 "속력을 키우지 않는다").
- 대안: XRI의 기본 던지기 속도(Throw On Detach) 사용. 평균화와 단계별 보정을 끼워 넣을 수 없어 쓰지 않는다.
- 대안: 컨트롤러 속도 대신 위치 차분으로 직접 속도 계산. 입력 디바이스 값이 더 직접적이라 우선 장치 속도를 쓰고, 노이즈가 심하면 차분으로 보완한다.

### 4. 핀 판정: 정지 대기 후 한 번에 확정

```
 [Idle] -> [Thrown] -> [Settling] -> [Judged] -> [ShowingResult] -> [Resetting] -> [Idle]
                           |
      모든 핀 속도 < 기준값이 ~1.5초 지속, 또는 최대 ~10초 경과
```

판정은 핀별로 수직 대비 기울기(초기 약 45도), 원위치 대비 이동 거리, 피트 트리거 진입 여부를 본다. 기준값은 설정 값으로 둔다. 공이 거터나 피트로 빠지면 공만 회수하고 같은 흐름을 탄다.

### 5. 로직 분리: 순수 C# 코어 어셈블리

`GameSession`(투구 기록, 총합, 재시작), 상태 머신의 상태 전이 규칙을 UnityEngine 참조가 없는 별도 어셈블리(asmdef)에 둔다. 입력은 "쓰러진 핀 수" 숫자 하나뿐이다. EditMode 테스트로 검증하고, 단계 B에서 프레임 규칙을 같은 어셈블리에 확장하며, 멀티플레이 시 결과만 동기화하는 구조와 맞는다.

- 대안: 하나의 MonoBehaviour에 모두 구현. 빠르지만 테스트가 어렵고 B 단계에서 점수 규칙을 얹을 때 다시 뜯어야 한다.

### 6. UI: 월드 공간 캔버스 + XRI UI 상호작용

보정 선택 화면과 결과 표시는 월드 공간 캔버스(TextMeshPro)로 만든다. 선택은 컨트롤러 레이로 한다. 결과 표시는 던지는 위치에서 보이는 전광판 위치에 둔다. 글자는 정위치에서 읽히는 크기로 잡는다.

### 7. 오디오

기존 효과음을 그대로 사용한다. 굴러가는 소리는 공 속도에 비례해 볼륨을 조절하며 루프하고, 핀 충돌음은 충돌 세기에 따라 재생하며, 10개가 모두 쓰러지면 `bowlingstrike.wav`를 재생한다. 공간 오디오(3D 사운드)를 쓴다.

### 8. 빌드·라이선스

Android(ARM64, IL2CPP), OpenXR의 Meta Quest 기능을 켠다. `bowling-club`은 CC BY 4.0이므로 `license.txt`를 유지하고, 게임 내 크레딧 또는 README에 출처를 표기한다. 공개 저장소이므로 서드파티 에셋의 재배포 조건을 확인한다.

## Risks / Trade-offs

- [볼링장 모델이 Quest 3S에서 무거움] → 한 레인을 직접 구성하고 FBX는 선별 재사용. 프로파일러로 일찍 측정한다.
- [손 속도에 노이즈가 있어 던지기가 불안정] → 0.1초 평균화와 보정 단계로 완화. 평균 구간 길이도 설정 값으로 둔다.
- [핀이 떨리거나 서로 파고듦] → 솔버 반복 상향, 단순 콜라이더, 슬립 시작. 문제가 계속되면 핀의 최대 침투 보정 속도를 조정한다.
- [핀이 기대 선 채 판정이 애매함] → 기울기 기준 각도를 설정 값으로 두고 실기기에서 맞춘다.
- [빠른 공이 핀을 통과] → 공을 Continuous로 설정하고 Fixed Timestep을 줄인다.
- [강한 보정이 실력을 가림] → 단계 선택으로 플레이어가 고르게 하고 기본값은 약함.
- [유니티 임포트 스케일이 어긋남] → 임포트 직후 레인 길이와 핀 높이를 실제 치수와 비교해 스케일을 고정한다.

## Open Questions

- UI 글꼴: 기본 TMP 글꼴은 한글을 지원하지 않는다. 한글 UI를 쓸지, 영어·숫자 위주로 갈지는 구현 때 정해도 스펙에 영향이 없다.
- FBX 장식물 중 최종적으로 남길 항목은 프로파일링 결과를 보고 정한다.
