## 2. 환경 구성 (한 레인)

- [ ] 2.1 `bowling club.fbx`의 임포트 스케일을 레인 길이와 핀 높이 기준으로 확인·고정한다. 검증: 씬에 배치한 핀 높이가 약 0.38m, 공 지름이 약 0.22m이다
- [ ] 2.2 레인·거터·피트·뒷벽을 단순 오브젝트와 박스 콜라이더로 구성하고, FBX에서 가벼운 장식만 골라 배치한다. UI 글꼴(한글 지원 여부)도 이 단계에서 정한다. 검증: Scene 뷰에서 레인이 약 18m 길이로 보이고 공이 바닥을 통과하지 않는다
- [ ] 2.3 라이팅을 구성한다(모바일 URP, 실시간 그림자 최소화, 필요 시 라이트맵). 검증: 실기기에서 어둡거나 번쩍이지 않고 읽힌다
- [ ] 2.4 Quest 3S 성능 예산을 프로파일링한다. 검증: 실기기에서 프레임 시간, 드로우콜, 삼각형 수를 기록하고 72Hz 이상을 유지함을 확인한다 (미달 시 장식 제거)

## 3. 핀 물리 (`pin-physics`)

- [ ] 3.1 핀 프리팹을 만든다(리지드바디, 질량 약 1.5kg, 캡슐+구 콜라이더, 낮은 무게중심, 낮은 반발 머티리얼). 검증: 씬에 놓으면 서 있고 떨리지 않는다
- [ ] 3.2 핀 10개를 삼각형으로 배치하고 슬립 상태로 시작한다. 검증: 플레이 시작 후 10개가 모두 움직이지 않는다
- [ ] 3.3 공 프리팹을 만든다(구 콜라이더, 질량은 핀의 4~5배, Continuous Dynamic, 낮은 마찰 머티리얼). 검증: 공을 빠르게 던져도 핀을 통과하지 않는다
- [ ] 3.4 쓰러짐 판정 컴포넌트를 구현한다(정지 대기, 기울기·이동 거리·피트 진입 기준, 기준값은 설정 값). 검증: 핀을 강제로 눕히거나 세워 둔 상태에서 EditMode/PlayMode 테스트가 기대한 개수를 반환한다
- [ ] 3.5 판정 대기 시간 상한을 구현한다. 검증: 핀을 계속 움직이게 둔 테스트에서 최대 시간 후 결과가 한 번만 확정된다
- [ ] 3.6 핀 리셋을 구현한다. 검증: 쓰러뜨린 뒤 리셋하면 10개가 모두 처음 위치로 돌아와 정지한다
- [ ] 3.7 효과음을 연결한다(굴러가는 소리는 속도 비례 루프, 핀 충돌음은 충돌 세기 비례, 10개 쓰러지면 스트라이크음). 검증: 실기기에서 굴릴 때 소리가 나고 핀을 맞힐 때 소리가 난다

## 4. 던지기 (`ball-throwing`)

- [ ] 4.1 공에 `XRGrabInteractable`을 설정하고 그립으로 잡기·놓기를 구현한다. 검증: 실기기에서 손 근처에서만 잡히고 멀면 반응이 없다
- [ ] 4.2 컨트롤러 속도 링 버퍼와 릴리스 속도 계산을 구현한다. 검증: 단위 테스트가 0.1초 평균과 순간 속도의 결과 차이를 확인한다
- [ ] 4.3 `ThrowAssistSettings`(순수 물리/약함/중간/강함, 평균화 여부와 보정 비율)를 만들고 보정 계산을 구현한다. 검증: 단위 테스트가 네 단계의 결과 방향과 속력을 확인한다(속력은 보정 전보다 커지지 않음, 강함이 중간보다 레인 방향에 가까움)
- [ ] 4.4 릴리스 시 XRI 기본 속도 대신 계산한 속도를 리지드바디에 적용하고 수직 속도를 제한한다. 검증: 실기기에서 던지면 공이 레인 방향으로 굴러간다
- [ ] 4.5 파울 라인 제한을 구현한다. 검증: 선을 넘어 놓으면 공이 던져지지 않고 공 반환 위치로 돌아간다
- [ ] 4.6 투구가 끝나면 던지는 위치 근처에 공을 다시 공급한다. 검증: 결과 확정 후 집을 수 있는 공이 나타난다
- [ ] 4.7 실기기에서 네 단계를 각각 던져 보고 보정 수치를 조정한다. 검증: 기본값 약함이 자연스럽게 느껴지고 단계 간 차이가 체감된다
